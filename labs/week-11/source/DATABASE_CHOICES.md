# CP41 

## 1. ทำไมโปรเจกต์นี้เลือก SQLite แทน MongoDB

โปรเจกต์นี้มีข้อมูลที่จัดเป็นโครงสร้างชัดเจน เช่น `users` และ `requests` โดยคำร้องแต่ละรายการเชื่อมกับผู้ใช้ผ่าน `requester_id` และมีการใช้ Foreign Key กับคำสั่ง `JOIN` เพื่อดึงข้อมูลจากหลายตาราง จึงเหมาะกับฐานข้อมูลแบบ Relational อย่าง SQLite มากกว่า

SQLite เก็บฐานข้อมูลไว้ในไฟล์เดียว ไม่ต้องตั้งเซิร์ฟเวอร์ฐานข้อมูลแยก เหมาะกับโปรเจกต์ขนาดเล็กที่ใช้ฝึกเขียน SQL ส่วน MongoDB จะเหมาะกับข้อมูลแบบเอกสารที่โครงสร้างยืดหยุ่นกว่า

## 2. ถ้าต้องเปลี่ยนไป MongoDB จะกระทบชั้นไหนบ้าง

กระทบชั้นฐานข้อมูลแน่นอน เพราะต้องเปลี่ยนจากตารางและ SQL ไปใช้ Collection และ Document รวมถึงต้องปรับวิธีค้นหา เพิ่ม แก้ไข และลบข้อมูล

ชั้น API หรือชั้นที่ติดต่อฐานข้อมูลก็ต้องแก้ด้วย เพราะคำสั่งจาก MongoDB Driver ทำงานแบบ asynchronous จึงต้องใช้ `async/await` หรือจัดการ Promise และส่งต่อผลลัพธ์ให้ส่วนที่เรียกใช้งานรอให้เสร็จอย่างถูกต้อง โค้ดที่เคยทำงานต่อทันทีหลังเรียกฐานข้อมูลอาจต้องปรับ รวมถึงการจัดการข้อผิดพลาดด้วย

ถ้าแยกโค้ดติดต่อฐานข้อมูลออกจากกติกาของระบบไว้ดี ชั้นอื่นอาจแก้น้อยลง และถ้ายังคงรูปแบบ JSON ที่ API ส่งกลับเหมือนเดิม ฝั่งผู้ใช้ก็อาจไม่ต้องแก้มาก แต่คำสั่ง SQL, `JOIN` และความสัมพันธ์ของข้อมูลต้องออกแบบใหม่ให้เข้ากับ MongoDB

## 3. async จำเป็นเมื่อไร ไม่จำเป็นเมื่อไร

ควรใช้ `async/await` เมื่อการทำงานต้องรอผลจากสิ่งอื่น เช่น ติดต่อฐานข้อมูลผ่านเครือข่าย เพราะการส่งคำขอและรอคำตอบใช้เวลา ระหว่างนั้น Node.js สามารถไปจัดการงานอื่นได้ และเมื่อได้ผลแล้วจึงทำงานต่อ

ถ้าใช้ SQLite ในเครื่องด้วยไลบรารีที่ทำงานแบบ synchronous และเป็นงานขนาดเล็ก ก็ไม่จำเป็นต้องใช้ `async/await` กับคำสั่งนั้น แต่ถ้าไลบรารี SQLite ที่เลือกใช้มี API แบบ asynchronous ก็ต้องจัดการแบบ async เช่นกัน

สรุปคือ จุดสำคัญอยู่ที่วิธีทำงานของไลบรารีและการรอผล ไม่ได้ตัดสินจากชื่อฐานข้อมูลเพียงอย่างเดียว โดยทั่วไป MongoDB ที่อยู่บนเซิร์ฟเวอร์อีกเครื่องต้องรอผลผ่านเครือข่าย จึงมักต้องใช้ async ส่วน SQLite ที่อ่านไฟล์ในเครื่องสามารถใช้แบบ synchronous ได้หากเลือกไลบรารีลักษณะนั้น
